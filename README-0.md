Ключевые архитектурные решения:

**Поток данных**: `HTTP → Controller → DTO → Service → Repository → БД`. Каждый слой знает только о соседнем через
интерфейс.

**Что где живёт**:

- **Module.php** — сам регистрирует DI-привязки и маршруты (самодостаточный модуль, подключается одной строчкой)
- **contracts/** — интерфейсы для DIP, все зависимости инвертированы
- **dto/** — иммутабельные объекты передачи данных с фабричным `fromArray()`
- **services/** — вся бизнес-логика: генерация слагов, проверка уникальности, контроль публикации
- **repositories/** — тупые трубы в БД, никакой логики
- **controllers/** — тонкие, только `DTO → сервис → ответ` + маппинг исключений в HTTP-коды
- **events/** — доменные события для расширяемости (OCP): подпишись и делай что хочешь, не трогая модуль
- **exceptions/** — иерархия доменных исключений вместо голых `RuntimeException`

Модуль сам определяет, в каком приложении работает (frontend/backend), и подставляет нужный namespace контроллеров. Если
нужно добавить бэкенд-контроллер категорий — просто создаёшь `controllers/backend/CategoryController.php` по аналогии.
